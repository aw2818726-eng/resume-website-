1. Ask: business task
The task is to find how annual members and casual riders use Cyclistic bikes differently, so marketing can design a strategy to convert casual riders into annual members.
Analyze Cyclistic's historical trip data (last 12 months, Oct 2025 to Sep 2026) to identify how annual members and casual riders differ in ride frequency, ride length, day of week, time of day, season, bike type and stations.
Stakeholders: Lily Moreno (director of marketing, manager), the marketing analytics team, and the executive team (approves recommendations, detail-oriented).
Plan (Ask, Prepare, Process, Analyze, Share, Act):
1. Prepare: get 12 months of Divvy trip data and load it into BigQuery.
2. Process: union the months, remove duplicates and bad records, add ride_length, day_of_week and similar fields.
3. Analyze: compare member_casual on ride count, average and median length, day, hour, month, bike type and top stations.
4. Share: visuals (Tableau, Looker Studio or Slides) with clear titles.
5. Act: top three recommendations, then add the case study to the portfolio site.

Schema (13 columns, identical in every file I inspected): ride_id, rideable_type, started_at, ended_at, start_station_name, start_station_id, end_station_name, end_station_id, start_lat, start_lng, end_lat, end_lng, member_casual.
Findings while preparing the files:
• The CSV inside the 202601 zip was named 202501-divvy-tripdata.csv in the copy I inspected, but its data is January 2026. Rename it to 202601-divvy-tripdata.csv if yours has the wrong name.
• Each file holds a few dozen rides from the end of the previous month (for example, 78 rides in June that started in May). Filter on started_at, not on the file name.
• Many rides, mostly e-bikes, have empty station names and IDs. This is normal and not a load error.
• Timestamps are Chicago local time but BigQuery labels them UTC. Do not convert time zones; the hours are already local.
• Keep the original CSVs in a raw_data folder and never edit them.
Data credibility (ROCCC):
Criterion	Assessment
Reliable	Trips are logged automatically by the bike system, so there is no manual entry. Some records were bad (negative or very short durations, test stations); 2.7% of rows were removed in cleaning.
Original	First-party data published by the bike-share operator (Divvy, run by Lyft). Cyclistic is a fictional company, so this is the closest real equivalent.
Comprehensive	Covers every trip in the system for 12 months. It has no rider ID, age, gender or pricing, and about 21% of rides have no start station.

Privacy: the data has no personal information, so you cannot tell who lives in the service area or whether a casual rider has bought multiple passes. Rides cannot be linked to a person. Findings describe rides, not individual riders.

Design decisions:
• Explicit schema on every load so all 12 tables have identical types and the union cannot fail on a mismatch.
• The raw union table trips_all_raw is never edited; all cleaning goes into a separate trips_clean table, so the original stays intact and the steps are documented.
• Files use snake_case names (a standing preference), for example trips_all_raw, trips_clean.
4. Loading the data into BigQuery
Project my-first-pro-504117, dataset cyclistic, location US. All 12 files were loaded from Cloud Shell (it reported every job DONE), then combined into one raw table.
Step 1: unzip into a clean folder (Cloud Shell; the zips were in the folder cap stone.zip):
mkdir -p ~/data
for z in ~/"cap stone.zip"/*-divvy-tripdata.zip; do unzip -o -q "$z" -d ~/data -x "__MACOSX/*"; done

[ -f 202501-divvy-tripdata.csv ] && mv 202501-divvy-tripdata.csv 202601-divvy-tripdata.csv

5. Process: cleaning
Cleaning writes to a new table, trips_clean, and leaves trips_all_raw untouched. Status: cleaning done. The step 1 counts and the final result are below.
Cleaning rules:
Rule
Why
Keep only rides that started between 2025-10-01 and 2026-09-30
Removes rides logged in the wrong month's file
Remove duplicate ride_ids (keep one)
35 duplicates found in the load check
Keep rides lasting 60 seconds to 24 hours
Under 1 minute = false starts; over 24 hours = lost or unreturned bikes; negative = bad data
Remove test and maintenance stations (names containing TEST, HUBBARD BIKE-CHECKING, CASSETTE, LYFT DRIVER)
Not real customer trips
Trim text and lowercase member_casual and rideable_type
Consistent values for grouping
Keep rides with missing station names
Mostly e-bikes; dropping them would remove millions of rides and bias the member versus casual comparison. Exclude them only in the station analysis
Do not convert time zones
Timestamps are already Chicago local time
Step 1: count what each rule removes (save these numbers for the write-up):
SELECT
  COUNT(*) AS total_rows,
  COUNT(*) - COUNT(DISTINCT ride_id) AS duplicate_ids,
  COUNTIF(started_at < '2025-10-01' OR started_at >= '2026-10-01') AS outside_12_month_window,
  COUNTIF(TIMESTAMP_DIFF(ended_at, started_at, SECOND) < 0) AS negative_duration,
  COUNTIF(TIMESTAMP_DIFF(ended_at, started_at, SECOND) BETWEEN 0 AND 59) AS under_1_minute,
  COUNTIF(TIMESTAMP_DIFF(ended_at, started_at, SECOND) > 86400) AS over_24_hours,
  COUNTIF(start_station_name IS NULL) AS null_start_station,
  COUNTIF(end_station_name IS NULL) AS null_end_station,

FROM `my-first-pro-504117.cyclistic.trips_all_raw`;

Step 2: create the clean table:
CREATE OR REPLACE TABLE `my-first-pro-504117.cyclistic.trips_clean` AS
SELECT
  ride_id,
  LOWER(TRIM(rideable_type))  AS rideable_type,
  started_at,
  ended_at,
  TIMESTAMP_DIFF(ended_at, started_at, SECOND) / 60.0 AS ride_length_min,
  FORMAT_TIMESTAMP('%A', started_at)                  AS day_of_week,
  EXTRACT(DAYOFWEEK FROM started_at)                  AS day_of_week_num,  -- 1 = Sunday
  FORMAT_TIMESTAMP('%B', started_at)                  AS month_name,
  EXTRACT(MONTH FROM started_at)                      AS month_num,
  EXTRACT(HOUR FROM started_at)                       AS start_hour,
  NULLIF(TRIM(start_station_name), '') AS start_station_name,
  NULLIF(TRIM(end_station_name), '')   AS end_station_name,
  start_lat, start_lng, end_lat, end_lng,
  LOWER(TRIM(member_casual)) AS member_casual
FROM `my-first-pro-504117.cyclistic.trips_all_raw`
WHERE started_at >= '2025-10-01' AND started_at < '2026-10-01'
  AND TIMESTAMP_DIFF(ended_at, started_at, SECOND) BETWEEN 60 AND 86400
  AND NOT REGEXP_CONTAINS(UPPER(CONCAT(IFNULL(start_station_name,''), IFNULL(end_station_name,''))),
          r'TEST|HUBBARD BIKE-CHECKING|CASSETTE|LYFT DRIVER')
QUALIFY ROW_NUMBER() OVER (PARTITION BY ride_id ORDER BY started_at) = 1;
Step 3: sanity check (expect only member and casual, and sensible bike types):
SELECT member_casual, rideable_type, COUNT(*) AS rides,
       ROUND(AVG(ride_length_min), 1) AS avg_min
FROM `my-first-pro-504117.cyclistic.trips_clean`
GROUP BY 1, 2 ORDER BY 1, 2;

Key findings:
• Weekends: casual riders peak on Saturday and Sunday and bottom out midweek. Members peak Tuesday to Thursday, which fits commuting.
• Ride length: casual rides are about 49% longer on average and 28% longer by the median.
• Time of day: members have two commuter peaks (about 08:00 and 17:00). Casual riders have no morning peak; their rides build through the day and peak at 17:00, with 15:00 to 18:00 strongest.
• Season: casual riding is far more seasonal. It goes from about 24k rides in January to about 346k in July, and casual riders are 40.8% of rides in July against 17.9% in January. Members stay steadier through winter.
• Stations: casual riders start mostly at lakefront and tourist spots: Navy Pier (49,557 rides), DuSable Lake Shore Dr & Monroe St, Michigan Ave & Oak St, Millennium Park, Shedd Aquarium, Theater on the Lake, Field Museum and Adler Planetarium.
• Bike type: both groups mostly use e-bikes (74.2% casual, 68.3% member), so bike type is not a strong difference.
Limits of the analysis:
• One year of data, so the seasonal pattern is not confirmed across years.
• The station ranking only counts rides with a start station (about 21% have none).
• The late-night casual share (55 to 59% between midnight and 03:00) is based on small counts and is not used in the recommendations.
• The data shows ride behavior, not who the riders are, so it cannot say why casual riders choose not to subscribe.

7. Act: top three recommendations for Lily Moreno's team
1. Target leisure riders at the lakefront stations. Run membership promotions at Navy Pier, Millennium Park, Shedd Aquarium and the other stations where casual riders start most of their rides.
2. Time campaigns for season and weekend. Run them from late spring through summer (May to Sep) and on weekends, when casual ridership peaks. Consider a summer or weekend-focused membership tier.
3. Pitch the membership on value for longer, leisure rides. Casual rides are about 49% longer on average, so a cost-per-ride argument fits. The hour data shows casual riders do not commute, so show that members use bikes for more than commuting.
Suggested next analysis for the executive team: test a seasonal pass, and compare cost per ride for typical casual users against an annual membership.
